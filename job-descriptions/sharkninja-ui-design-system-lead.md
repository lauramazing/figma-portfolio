This role sits within SharkNinja's DTC (direct-to-consumer) digital organisation. The aim is to establish a single source of truth that multiplies output and streamlines the development lifecycle.

## Role: UI Design System Lead, DTC

### Core Responsibilities

**Design System Ownership**
- Own and evolve SharkNinja's UI design system across all DTC digital properties
- Define and maintain design tokens, component libraries, patterns and guidelines
- Continuously audit and improve the system against product needs, accessibility standards and best practices
- Balance consistency with flexibility — establish standards while leaving room for product/market judgment

**Component & Pattern Development**
- Design, build and maintain a comprehensive reusable UI component library for web and digital touchpoints
- Use Figma variables, component architecture and token structures to create scalable design foundations that map to coded components
- Collaborate with front-end engineering to ensure accurate implementation and maintainability
- Establish versioning, contribution and governance processes

**Cross-Functional Enablement**
- Primary point of contact and subject matter expert for the design system
- Develop documentation, guidelines and training resources for adoption and contribution
- Build alignment across design, engineering and product through influence, not authority

**Quality & Accessibility**
- Ensure all components meet WCAG 2.1 AA accessibility standards
- Define and uphold UI quality standards across the DTC estate

**Collaboration & Influence**
- Partner with Engineering on tokens, component libraries, design-to-code handoff and development workflows
- Present design system roadmap and impact to senior stakeholders

## About You (Requirements)

- 5+ years in UX or Product Design, with 3+ years focused on design systems
- Demonstrated experience building and scaling a design system in a product-led organisation
- Expert Figma proficiency — variables, component architecture, auto layout, scalable library structures

- Strong systems thinking — patterns, consistency, scale, reuse
- Experience defining tokens, reusable components, patterns, documentation and contribution models
- Working knowledge of HTML and CSS; understanding of how UI components are implemented in code
- Strong understanding of WCAG 2.1 AA accessibility standards
- Comfortable operating in a governance role — setting standards, running reviews, managing contributions
- Excellent communication and stakeholder management skills

## Gap Analysis

### ⚠ Where the application feels tailored to a different role

- **Enterprise vs ecommerce framing**: IBM is deeply enterprise B2B software. The CV and portfolio framing (governance at scale, acquired products, enterprise product complexity) reads as an enterprise design systems story. SharkNinja wants a DTC/ecommerce lens — consumer-facing web, marketing touchpoints, checkout flows, product pages.
- **"Visual Lead" title vs "Design System Lead"**: The IBM title is "Visual Design Lead" — the CV will need to make clear this encompasses design systems leadership, not just visual craft.
- **No native mobile emphasis needed here** (unlike Zopa) — this role is web/DTC, which is actually a better fit.
- **Figma variables depth**: The JD asks specifically about Figma variables and token-to-code mapping. If the portfolio was written before Figma variables were central to the IBM kit work, this may need a more explicit callout.
- **ecommerce/DTC context is explicitly preferred**: Worth acknowledging this gap honestly if asked, and bridging with transferable parallels (multi-market consistency, high-velocity component delivery, consumer-facing quality bar).
